Agent Observability

Instrumentation for AI agents so you can see a session, a tool call, and a memory hydrate the way you already see a request in production.

Problem

Agents fail quietly. The HTTP layer returns 200 while the model called the wrong tool, skipped memory, or burned the window. Logs that only say "invoke completed" are not enough to operate the system.

What I built

Observability around agent sessions: traces and metrics for invoke, MCP session lifecycle, and memory hydrate and persist. OpenTelemetry in the platform SDK so graphs emit spans like any other service. Datadog for the production view, including SLOs for the AI stack. The point is operability, not a dashboard for its own sake.

Stack

  • OpenTelemetry for traces from agents and the gateway
  • Datadog for metrics, traces, and SLOs
  • Python services on AWS ECS

Outcome

When an agent misbehaves, there is a session to inspect, not a guess. This page does not cite SLO percentages or traffic numbers.
