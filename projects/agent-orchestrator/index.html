Agent Orchestrator

A job control plane for multi-agent work: split an objective into tasks, execute them, and inspect the run without embedding that loop in every product.

Problem

A single agent call is easy. A piece of work that needs several agents, retries, and a human-visible trail is not. Teams then grow ad hoc loops, lose job state when a process dies, and have no place to look at the swarm while it runs.

What I built

An orchestrator service with a REST API and an inspection UI. Jobs decompose an objective into tasks, run them through the gateway and agent runtime, and aggregate results. A scheduler and event bus keep that durable. Slack is a client of the same control plane, not a second brain: the orchestrator still owns inference, memory, auth, and audit. A related pipeline engine dispatches agent stages over work items, with kill switches and webhooks, when the work is a factory line instead of a one-shot job.

Stack

  • Python and FastAPI for the job engine
  • PostgreSQL for job and task state
  • React for the swarm-inspection UI
  • AWS ECS for the runtime

Outcome

Multi-step agent work has a job object, a schedule, and a UI. Chat clients and Slack are transports. This page does not cite throughput or uptime numbers.
