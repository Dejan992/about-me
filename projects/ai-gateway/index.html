AI Gateway Platform

A gateway in front of multiple AI providers so apps do not each implement routing, auth, and tenant config.

Problem

Teams calling providers directly scatter API keys, tenant settings, and failover logic across services. A provider change or config edit then means a deploy in every caller. Voice transcription and admin work tend to grow as one-off services beside that mess.

What I built

An enterprise gateway that routes requests across providers. OAuth 2.1 for authentication. Multi-tenant configuration that can hot-reload without taking the gateway down. A React admin UI, a service registry, and a voice transcription microservice sit on the same platform.

Stack

  • Python and FastAPI for the gateway
  • React for the admin UI
  • DynamoDB and Redis for config and runtime state
  • AWS CDK for the infrastructure

Outcome

Callers talk to one gateway. Provider routing, tenant config, and reloads are platform work, not something each app has to own. This page does not cite traffic or uptime numbers.
