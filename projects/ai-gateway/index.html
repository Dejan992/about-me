AI Platform Infrastructure

Production infrastructure for an MCP gateway: deploy, config, and runtime so AI clients have one operable front door.

Problem

An MCP gateway is not useful if it only runs on a laptop. Teams need CDK, containers, config that can change without a bounce, and enough telemetry to see when a session dies. That layer is easy to skip while the product features grow.

What I built

The infrastructure under the gateway. AWS CDK and ECS for the runtime. DynamoDB and Redis for tenant config, with hot reload so a settings change does not take the process down. Docker, CI, and the deploy path. Wiring so MCP sessions and agent invokes show up in Datadog. I did not build every product surface on that stack; infra is the wheelhouse.

Stack

  • AWS CDK, ECS, and Docker
  • DynamoDB and Redis for config and runtime state
  • Python and FastAPI for the gateway process
  • MCP as the client protocol
  • Datadog for the production view

Outcome

The gateway is a production service: deployable, configurable, and observable. This page does not cite traffic or uptime numbers.
